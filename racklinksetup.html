RackLinkSetup

What It Does

RackLinkSetup.exe is a commissioning tool for RackLink Premium+ PDUs. When a vendor or engineer runs it, the script:

  1. Changes the default password and enables HTTPS
  2. Sets the PDU name, hostname, and outlet names
  3. Configures the time zone and NTP server
  4. Updates the firmware (if a newer .bin file is present)
  5. Enables RackLink Cloud and claims the device into the correct space
  6. Updates the RackLink Inventory Smartsheet with device details

What the Vendor Receives

A zip file downloaded from the project's GitHub release link. It contains:

  • RackLinkSetup.exe — the commissioning tool (self-updating)
  • VENDOR GUIDE.md — step-by-step instructions for the vendor
  • Firmware .bin file — the approved firmware package

Self-updating: The vendor only downloads the zip once. On every subsequent launch, the exe checks for a newer version and updates itself automatically. Vendors do not need to re-download anything when we push fixes.

Vendor Prerequisites

The vendor needs:

  • A laptop with wired Ethernet (for direct connection to ETH2) and Wi-Fi (for internet)
  • Static IP configured on the Ethernet adapter: 192.168.1.243 / 255.255.255.0
  • LAN1 (ETH1) of the RackLink connected to the building network

The vendor can also connect over the network (VDI, vendor shop) by selecting "Network / Other" and entering the PDU's IP address.

Smartsheet Integration

Each commissioning run adds or updates a row in the RackLink Inventory Smartsheet with:

  • PDU name, serial number, MAC addresses, model, firmware version
  • ETH1 and ETH2 IP addresses
  • Cloud connection and claim status
  • Automated notes when the IP situation needs follow-up

Firmware

The firmware .bin file is included in the release zip. The script handles version comparison automatically:

  • Newer firmware available — prompts the vendor to confirm
  • Already up to date — skips silently
  • No firmware file present — skips the step entirely

Re-running

The script is designed to be re-run safely. Common reasons to re-run:

  • After MAC whitelisting, to update the Smartsheet with the correct network IP
  • After a firmware update was skipped, to apply it later
  • To correct a PDU name or outlet names
